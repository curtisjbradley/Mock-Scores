# Backend guidance

## Architecture

- Express 5 API using CommonJS, with PostgreSQL accessed through `pg` and raw SQL.
- `src/app.ts` starts the server and loads `appService.ts`.
- Authentication uses JWTs through `jose`; `verifyUser` protects organizer and coach route areas at the router level in `appService.ts`.
- Route handlers delegate business logic directly to `providers/organizerProvider.ts` or `providers/coachProvider.ts`; there is intentionally no service layer.
- Routes include `/api/auth/*`, organizer tournament routes, coach routes, public `/score/:scorerID`, and `/webhooks/*`.

## Implementation rules

- Put new routes under `src/routes/` in the applicable area. Handlers should only validate input, call a provider, and send the HTTP response.
- Keep business logic in the applicable provider, not the route handler.
- Use the error helpers in `src/errors.ts`; never expose stack traces or internal errors to clients.
- UUIDs are generated by PostgreSQL with `gen_random_uuid()`, never in application code.
- Keep row interfaces in `src/types/dbtypes.ts` and cross-workspace API types in `shared/src/index.ts`.
- The schema source of truth is `documentation/TableSetup.sql`. Add (do not alter) a numbered migration for every schema change; migrations are applied manually.

## Tests

- Backend tests are integration-style route-plus-provider tests using Jest and `supertest` under `testing/tests/`.
- Database mocks are in `testing/mocks/`; `db.ts` exports the mock `pg` pool.
- Run `npm test -w backend` (or root `npm test`) for relevant backend changes.
